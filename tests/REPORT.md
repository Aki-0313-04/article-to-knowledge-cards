# 本地测试记录

日期：2026-11-23

## 方法

本次开发助手读取 Skill 与本地原文，手工执行提炼流程，将实际卡片保存到 `outputs/`，再逐卡回查输入。不使用外部资料或生成脚本，也没有启动独立模型或子代理。输入均为自写测试文章，不是对真实研究或产品的事实介绍。

检查标准：覆盖文章主干；一卡一点且无重复；四类必需内容完整；每个事实、例子、自测答案都可回查；保留观点归属与限制条件；不凑数量。措辞无需逐字一致。

## 根据试跑完善

技术与观点文本的审查表明，仅写“忠于原文”还不足以明确个案、主观报告和建议的表达边界。已在 Skill 中明确要求保留否定、时间、单位、适用对象及限制条件，区分事实、观点、建议、推测，不把个案或主观感受写成通用因果结论。

观点文章含两条冲突的会议记录。已补充规则：标明冲突及其位置，继续提取其他明确知识，不选择一方、不拆成互相矛盾的事实卡。保存的输出已按完善后的规则复核。

## 范围与局限

本次已覆盖本地 Markdown/TXT、正文提炼、正常数量、少于 5 张、零知识点、去重、例子与自测、限定条件、观点、冲突、嵌入指令。未实际测试大文件分段、其他编码、损坏文件或不同宿主的自动发现；未执行不支持的网页/PDF/Anki/界面操作。以上不冒充自动化通过项。
