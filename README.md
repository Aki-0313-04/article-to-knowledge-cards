# make-knowledge-cards

把粘贴的文章或本地 Markdown/TXT 文件整理成通常 **5–8 张知识卡片**，方便理解、记忆和自测。这是由支持 Skill 的 AI 助手执行的指令型 Skill，需要在相应宿主中使用；项目不包含独立应用、命令行转换程序或图形界面。

## 项目解决什么问题

长文章的重点容易被铺垫、重复表达和细节淹没，普通摘要也不一定适合逐点复习。本项目指导助手选出文章主干，将其整理成“一张卡片只讲一个知识点”的学习材料，并保留原文依据，便于回查。

## 主要功能

- **支持两类输入**：用户粘贴的正文，以及本地 `.md`、`.markdown`、`.txt` 文件；文件默认按 UTF-8 读取。
- **提炼与去重**：优先选择重要定义、机制、区别、方法、结论和适用边界，合并重复内容。
- **生成完整卡片**：每张包含标题、核心知识、简明解释，以及原文例子或自测问题；自测题附参考答案，每张均附原文依据。
- **忠于原文**：不补充外部知识或编造例子，保留限定条件与作者观点归属；发现原文冲突时标明，不擅自裁决。
- **按信息量决定数量**：通常输出 5–8 张；不足 5 个独立知识点时减少数量并说明，没有可靠知识点时不生成卡片。
- **输出 Markdown**：默认在对话中展示；用户要求保存时，才写入指定位置，并保留输入文件。默认使用原文语言，也可指定输出语言。

暂不支持网页抓取、PDF 解析、Anki 导出或图形界面。遇到网址或 PDF，请先自行取得正文，再粘贴或另存为支持的文本格式。此 Skill 整理原文主张，不承担外部事实核验。

## 安装方法

前提：使用支持 `SKILL.md` 格式的 AI 助手；读取或保存本地文件时，宿主还需具备相应文件访问能力。此 Skill 本身无需安装 Python、Node.js、额外库或配置 API 密钥；宿主的账号与运行环境需自行准备。

### 在 Codex 中安装

将本项目的整个 `make-knowledge-cards/` 文件夹复制到目标项目的 `.agents/skills/` 下。安装后的结构应为：

```text
<目标项目>/
└── .agents/
    └── skills/
        └── make-knowledge-cards/
            ├── SKILL.md
            └── agents/
                └── openai.yaml
```

例如，在本项目根目录运行以下 PowerShell 命令，可安装到当前项目：

```powershell
New-Item -ItemType Directory -Force -Path .\.agents\skills | Out-Null
Copy-Item -LiteralPath .\make-knowledge-cards -Destination .\.agents\skills -Recurse
```

若要供当前用户的多个项目使用，也可复制到 `~/.agents/skills/` 下，保持相同的 Skill 文件夹结构。两种安装位置任选其一即可，无需初始化 Git。Codex 会自动检测 Skill；若未显示，重启 Codex。目录与加载方式参见 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。

其他宿主请使用其文档规定的 Skill 目录。只需复制 `make-knowledge-cards/`；根目录的 `tests/` 是开发测试材料，不是运行依赖。

### 不安装，直接在当前项目试用

让具备本地文件读取能力的助手读取规则后执行：

```text
请读取当前项目的 make-knowledge-cards/SKILL.md，按其中规则将下面的正文转换成知识卡片：
<粘贴文章正文>
```

这可用于本地试用；仅将 Skill 文件夹放在项目根目录，并不等于已安装到宿主的自动发现目录。

## 使用方法

**方式一：粘贴正文。** 安装并确认 Skill 可用后，发送：

```text
请使用 $make-knowledge-cards 整理下面的文章：
<粘贴文章正文>
```

**方式二：读取本地文件。** 在本项目中可使用随附的测试文章：

```text
请使用 $make-knowledge-cards 读取 tests/inputs/technical.md，生成知识卡片。
```

在其他项目中，请替换成助手可访问的实际路径；含空格的路径应完整引用。

**保存结果或指定语言：** 在请求后追加“将结果保存到 cards.md”或“请用中文输出”。没有保存要求时，仅在对话中返回 Markdown。

## 输入输出示例

输入：

```text
本项目每周五进行资料归档。
换句话说，每到星期五，本项目会归档资料。
```

输出：

```markdown
来源：用户提供的正文；共 1 张

原文可独立提炼的知识点不足 5 个，重复表达已合并。

### 卡片 1：项目归档时间
- **核心知识**：本项目每周五进行资料归档。
- **简明解释**：第二句以“星期五”重复了同一安排。
- **自测问题**：本项目每周何时归档资料？
- **参考答案**：每周五。
- **原文依据**：正文第 1、2 句。
```

这个短例只有一个独立知识点，因此输出 1 张，不强行凑到 5 张。措辞可以变化，但应遵守去重和原文依据要求。

常规篇幅示例见 [技术说明输入](tests/inputs/technical.md) 和 [6 张卡片输出](tests/outputs/technical.md)，其中也展示了如何使用原文已有的例子。

## 本地验证

[tests/REPORT.md](tests/REPORT.md) 记录五类自写文章的手工试跑、逐卡审查和规则改进。测试不是独立模型评测，也不保证所有文章都能得到同等质量。

使用官方 skill-creator 自带的工具验证（Python 需要 PyYAML；工具不随本仓库分发）：

```text
python <skill-creator目录>/scripts/quick_validate.py ./make-knowledge-cards
```

结构验证不能代替内容审查。修改 Skill 后，重新用 `tests/inputs/` 中的原文生成卡片，对照原文检查重要性、去重、事实依据、限定条件和数量，而非逐字匹配示例输出。
